# 数据缺口与补数规格

先把业务问题写成可检验的命题，例如“某商品降价后七天订单是否回升”。检查已有文件的实际表头、样例、键和覆盖周期；只有字典而没有数据时，保留“定义已知、覆盖待验”。不要从字段名推断采集成功。

## 推导最小补数范围

- **先列已有证据。** 记录表、字段、行粒度、窗口和缺失情况。区分快照与历史、累计与区间、缺失与实测零。分别说明证据能回答什么，哪一步无法完成。
- **找到缺失的连接。** 对每个结论标出所需实体或事件、关联方向和可能的一对多关系。不同身份体系需要映射表；排序或名称相同不能证明是同一实体。请求前先确认现有字段能否推导所需指标。
- **把需求写成可交付数据。** 给出优先级、提供方或待确认联系人角色、行定义、主键和关联键、必要字段、单位/时区、窗口与样例。明确缺失语义、重复或迟到记录如何识别。根据任务区分一次性回溯与后续定时更新，仅要求影响业务判断的字段。
- **约定可复算的验收。** 按数据特性核查唯一性、必填与取值、覆盖、关联成功率、聚合前后数量或金额。能定位到异常行。阈值由业务双方给定；首次交换可先报告分布及待决阈值。记录未补齐会影响的具体结论。

## 交付

给业务方一张“要作的判断｜已有证据｜无法回答的原因｜优先补什么”表。给数据方提供最小字段清单、关联示意、一行虚构样例和验收办法。若取得新样本，按同一规格检查，并分别列出已解除和仍存在的缺口。

## 虚构示例

商品表显示商品 P7 关联 12 条短片，运营想按短片比较成交。现表只有商品级累计数量；先请求“短片 ID × 商品 ID × 统计日”的曝光、点击和可归因订单，附归因窗口与订单去重规则。如果一条订单能关联多条短片，另需确认归因权重。验收时用同一日期和归因口径对照来源汇总，同时列出未匹配商品。12 条短片不能推导出其中任何一条的成交。
