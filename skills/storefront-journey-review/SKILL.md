# 独立站转化路径复查

先把目标写成访客可以完成的一个动作，例如「首次到访的手机用户，从首页找到指定商品的尺寸表」。用户若已指定目标和入口，沿用其说法。目标不明确时，从入口文案推定访客意图，说明这个假设；若另一个合理目标会改变优先级，再请用户确认。

## 走一遍访客路径

1. 记下入口、起始状态和完成标志。起始状态只保留可能影响结果的条件，例如商品规格、是否登录、是否已有购物车、语言、地区或视口宽度。完成标志应能观察，例如「购物车里出现选中的规格」。
2. 顺着访客看到的提示操作。对关键一步并排记录「上一屏答应了什么」「按了什么」「下一屏实际出现什么」，保留足以定位的页面、控件文字或截图。重点看前一步所选内容能否带到下一步，以及失败后访客能否恢复。如果只有截图，写清画面能证明什么，把点击结果留到有交互条件时核验。
3. 若任务是验收改版，将原指南各项映射到对应路径和页面，分别标出已落实、部分落实、仍可复现或待验证。保留原编号，新发现另列。同一个原因影响多个页面时可合并讨论，并列出受影响的入口。
4. 区分现场观察、影响推断和待确认的业务规则。例如「切换尺码后到货日期没有变化」可以观察；「顾客可能以为两款同时到货」是推断；预计到货日期如何计算应由业务确认。涉及未确认的规则时，写出确认哪条规则会改变方案。量化流失或转化变化需要相应数据。

## 按本轮目标排优先级

| 优先级 | 判断依据 |
| --- | --- |
| P0 | 目标访客在主要入口无法完成关键动作，或继续会造成高代价错误，例如把错误的规格带入结算。 |
| P1 | 目标仍可完成，但访客需要猜、折返或重做，对购买决定有实质影响。 |
| P2 | 路径可理解且可完成，调整主要改善阅读、操作便利或视觉一致性。 |

每项写出排序理由。证据状态单独写，待验证项指出最短核实办法及「若属实」会影响哪一步。没有访问数据时，用已发现的受影响入口描述范围。

## 写成可以开会讨论的问题

先让读者看清具体问题和使用场景，再用一句白话说清怎么改。以下是一项问题的模板，可按交付格式裁剪。

| 字段 | 要填写的内容 |
| --- | --- |
| 编号、级别与证据 | 沿用旧编号或指定新编号。写级别、理由和证据状态，附截图或复现入口。 |
| 具体问题 | 在哪个页面点了什么，预期看到什么，实际看到什么。 |
| 用户场景 | 什么人带着什么任务走到这一步，缺了哪条信息或哪个动作，他接下来会怎样尝试。 |
| 建议怎么改 | 用一句白话写清控件放哪、显示什么、点后去哪里。必要时举一个按钮名称或页面状态的例子。 |
| 需要拍板的细节 | 只列会改变实施方案的业务分歧，交代各个选项对访客的具体影响。 |
| 验收 | 给出复测起点、动作和可见的成功结果。若修改涉及其他入口、异常或恢复路径，再给出相应验收条件。 |

汇总时先列最影响目标的几项，再给逐项讨论稿。若用户要逐项讨论，每项都应能独立读懂。是否做原版与修改后对照图、是否导出 PDF，按交付需要决定。

## 在同样条件下复测

选同一入口、相同身份及新旧版本都可用的测试商品，让浏览器从同等状态分别开始。例如两侧各用一个空购物车，避免旧版加过的商品掩盖新版问题。重复原先的操作，比较相同步骤的可见结果。记录日期或版本，以及可能影响结果的设备、地区和实验分组。无法取得旧版时，可引用带日期的旧截图，把当前实测与历史记录分开。

用「已通过」「仍可复现」或「待验证」记录结果，并给出对应证据。仅有设计稿时，可以核对控件位置与文案；只有实际跑过的操作才能标为交互已通过。路径打通后，如需判断转化率是否改善，另核对该路径的事件和统计口径。

## 模拟示例

假设一家茶具店要让手机访客从商品列表把所选容量加入购物车。以下数据为演示设定。

**J-01 · P0 · 模拟复现**　列表里点「600 毫升」会打开详情页，主图仍是大壶，但容量选项复位成 300 毫升。直接点「加入购物车」，购物车显示 300 毫升。主入口会带入错误规格。

**用户场景**　顾客已在列表比较过两种容量，准备买大壶。进入同一款茶壶的详情页时，他有理由以为刚才的选择还在。

**建议怎么改**　从列表进入时，把所选容量带到详情页，让选中的容量、价格和加入购物车的规格一起更新。若该容量刚售罄，保留原选择并提示缺货，让顾客自己选替代容量。

**验收**　在同一地区、相同手机视口、相同库存及空购物车下，从列表点 600 毫升。新版详情应选中 600 毫升，加入后购物车同样显示 600 毫升。再从无规格参数的商品直达链接进入，检查默认规格及所示价格符合该商品规则。售罄分支用对应的测试库存另验。
